TASK 5 — FIREBASE LOGGING, AUTOMATION & DATA EXPORT

1. Objective

The objective of this task is to extend the Firebase-based IoT monitoring system by implementing automatic appliance control, historical sensor-data logging, timestamp-based records, dashboard visualization, and CSV data export.

The completed system monitors temperature, humidity, and light intensity using an ESP32 with DHT11 and LDR sensors. The collected data is transmitted to Firebase Realtime Database. The system supports both manual and automatic bulb control based on the LDR threshold. Historical readings are stored with timestamps and can be viewed through the dashboard and exported as CSV data.

2. Complete IoT System Objective

The complete IoT system is designed to:

  • Monitor temperature using DHT11.
  • Monitor humidity using DHT11.
  • Monitor ambient light using an LDR.
  • Send sensor data from ESP32 to Firebase.
  • Display real-time sensor values on a web dashboard.
  • Provide manual bulb control.
  • Provide automatic bulb control based on light intensity.
  • Allow selection between Manual and Automatic modes.
  • Store historical sensor readings in Firebase.
  • Record timestamped sensor values.
  • Record bulb status and operating mode.
  • Display historical data on the dashboard.
  • Visualize sensor data using graphs.
  • Export recorded data as CSV.
  • Provide a cloud-based monitoring and control system.

5. LDR-Based Light Monitoring

An LDR (Light Dependent Resistor) is used to measure the surrounding light level.

The resistance of an LDR changes according to incident light.

The ESP32 reads the LDR through an analog input.

Example:

7. Automatic Bulb Control

In Automatic Mode, the ESP32 automatically controls the bulb according to the LDR reading.

The basic logic is:

LDR value indicates DARK

        ↓

Bulb ON

LDR value indicates BRIGHT

        ↓

Bulb OFF

A threshold value is used to determine whether the environment is considered dark or bright.

Example:

LDR Threshold = 2000

Depending on the actual LDR circuit configuration, the comparison direction may need to be reversed.

Therefore, the threshold must be experimentally calibrated using actual sensor readings.

10. LDR Threshold Calibration

The LDR threshold should not be selected randomly.

The calibration procedure is:

Step 1

Observe the LDR value under normal bright-room conditions.

Example:

Bright condition = 3200

Step 2

Observe the LDR value under dark conditions.

Example:

Dark condition = 900

Step 3

Select a threshold between the two conditions.

Example:

Threshold = 2000

Step 4

Test the bulb operation.

Bright → Bulb OFF

Dark → Bulb ON

Step 5

Adjust the threshold if the bulb switches incorrectly.

The final threshold should be documented in the project report.

24. Limitations of the Current Prototype

The current prototype has several limitations:

  • DHT11 has limited accuracy compared with industrial-grade sensors.
  • LDR provides a relative light measurement rather than a calibrated lux measurement.
  • LDR readings depend on the sensor circuit and environmental conditions.
  • Firebase depends on Internet connectivity.
  • Relay switching introduces mechanical switching limitations.
  • The prototype is designed primarily for demonstration and educational purposes.
  • The current system does not provide industrial-grade environmental sensing.
  • Historical storage can grow continuously if logging is performed at a very short interval.
  • Authentication and database security rules must be properly configured before real-world deployment.

25. Future Improvements

Possible future improvements include:

Hardware

  • Replace DHT11 with a higher-accuracy temperature/humidity sensor.
  • Use a calibrated lux sensor instead of an LDR.
  • Add additional environmental sensors.
  • Add current and energy monitoring.
  • Use a solid-state switching device where appropriate.

Software

  • Add real-time notifications.
  • Add configurable LDR thresholds.
  • Add date/time range filtering.
  • Add automatic daily/weekly reports.
  • Add improved dashboard visualization.
  • Add user-specific access control.
  • Add data aggregation to reduce database storage.
  • Add offline buffering when Internet connectivity is lost.

Data Analysis

  • Temperature trend analysis.
  • Humidity trend analysis.
  • Light-level analysis.
  • Bulb operating-time calculation.
  • Energy-consumption analysis.
  • Automatic anomaly detection.

26. Final Learning Reflection

Through this task, I learned how an IoT system can be extended beyond real-time monitoring by adding cloud-based historical data logging, automation, visualization, and data export.

I learned how Firebase Realtime Database can store both current system values and historical records. I also understood the importance of timestamps when analysing sensor data over time.

Implementing Manual and Automatic modes helped me understand how sensor-based decision logic can be combined with cloud control. LDR threshold calibration showed the importance of testing actual sensor values instead of selecting control limits arbitrarily.

The CSV export feature demonstrated how IoT data can be converted into a format suitable for further analysis using spreadsheet and data-processing tools.

Overall, this task improved my understanding of ESP32, sensors, Firebase, cloud databases, automation logic, dashboard development, historical data management, and IoT system integration.
