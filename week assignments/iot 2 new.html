IoT Session — Task 2: Adafruit IO Dashboard & MQTT

1. Overview

Objective

The objective of this task is to develop a cloud-connected IoT system using an ESP32, MQTT protocol, and Adafruit IO. The system allows a user to control an LED remotely through an Adafruit IO web dashboard.

Problem Being Addressed

In the previous task, the LED was controlled through a webpage hosted directly by the ESP32. This method generally requires the user and ESP32 to be connected to the same local network.

This task extends the system by introducing cloud-based communication. Adafruit IO acts as the cloud platform, allowing the ESP32 to exchange data with a remote dashboard using the MQTT protocol.

Project Summary

The ESP32 connects to the Internet and establishes an MQTT connection with the Adafruit IO broker. A feed is created in Adafruit IO for LED control. The dashboard contains a control element that publishes an ON or OFF value to the feed. The ESP32 subscribes to this feed and changes the LED state according to the received message.

Basic operation:

Adafruit IO Dashboard → MQTT Broker → ESP32 → LED

2. Concepts

Adafruit IO

Adafruit IO is a cloud-based IoT platform that allows devices to send, receive, visualize, and control data over the Internet.

It provides features such as:

  • Feeds
  • Dashboards
  • Data visualization
  • MQTT communication
  • Device connectivity
  • Cloud-based control

In this project, Adafruit IO is used to provide a remote dashboard for controlling the ESP32 LED.

MQTT

MQTT (Message Queuing Telemetry Transport) is a lightweight messaging protocol commonly used in IoT systems.

MQTT uses a publish/subscribe communication model instead of direct device-to-device communication.

The three main components are:

  1. Publisher
  2. Subscriber
  3. Broker

MQTT Publisher

A publisher sends messages to an MQTT topic.

In this project, the Adafruit IO dashboard acts as the publisher when the user changes the LED control value.

For example:

ON

or

OFF



MQTT Subscriber

A subscriber receives messages from a topic.

In this project, the ESP32 acts as the MQTT subscriber.

The ESP32 subscribes to the LED control feed and waits for messages from Adafruit IO.

MQTT Broker

The MQTT broker receives messages from publishers and forwards them to subscribers.

In this project, Adafruit IO's MQTT broker performs this function.

The communication can therefore be represented as:

MQTT Topic / Feed

An MQTT topic is the logical communication channel through which messages are exchanged.

Adafruit IO uses feeds as the data channels for MQTT communication.

Example feed:

username/feeds/bulb-control

The ESP32 subscribes to this feed.

When the dashboard publishes a new value, the ESP32 receives it through the MQTT connection.

3. System Design

System Architecture

The complete system contains four major elements:

User → Adafruit IO Dashboard → MQTT Broker → ESP32 → LED

Data Flow

  1. The ESP32 connects to the Internet using Wi-Fi.
  2. The ESP32 connects to the Adafruit IO MQTT broker.
  3. The ESP32 subscribes to the LED control feed.
  4. The user opens the Adafruit IO dashboard.
  5. The user selects the LED ON or OFF control.
  6. Adafruit IO publishes the corresponding value.
  7. The MQTT broker receives the message.
  8. The broker forwards the message to the ESP32.
  9. The ESP32 processes the received MQTT message.
  10. The ESP32 changes the LED GPIO state.

10. Implementation

Complete ESP32 Source Code

#include <WiFi.h>

#include "Adafruit_MQTT.h"

#include "Adafruit_MQTT_Client.h"

#define WIFI_SSID "YOUR_WIFI_NAME"

#define WIFI_PASSWORD "YOUR_WIFI_PASSWORD"

#define AIO_SERVER "io.adafruit.com"

#define AIO_SERVERPORT 1883

#define AIO_USERNAME "YOUR_ADAFRUIT_USERNAME"

#define AIO_KEY "YOUR_ADAFRUIT_IO_KEY"

#define LED_PIN 2

WiFiClient client;

Adafruit_MQTT_Client mqtt(

  &client,

  AIO_SERVER,

  AIO_SERVERPORT,

  AIO_USERNAME,

  AIO_KEY

);

Adafruit_MQTT_Subscribe bulbControl =

  Adafruit_MQTT_Subscribe(

    &mqtt,

    AIO_USERNAME "/feeds/bulb-control"

  );

void setup() {

  Serial.begin(115200);

  pinMode(LED_PIN, OUTPUT);

  digitalWrite(LED_PIN, LOW);

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

  Serial.print("Connecting to Wi-Fi");

  while (WiFi.status() != WL_CONNECTED) {

    delay(500);

    Serial.print(".");

  }

  Serial.println();

  Serial.println("Wi-Fi connected");

  Serial.print("IP Address: ");

  Serial.println(WiFi.localIP());

  mqtt.subscribe(&bulbControl);

}

void connectMQTT() {

  int8_t ret;

  if (mqtt.connected()) {

    return;

  }

  Serial.print("Connecting to Adafruit IO...");

  while ((ret = mqtt.connect()) != 0) {

    Serial.println(mqtt.connectErrorString(ret));

    mqtt.disconnect();

    delay(5000);

  }

  Serial.println("Connected to Adafruit IO");

}

void loop() {

  connectMQTT();

  mqtt.processPackets(1000);

  Adafruit_MQTT_Subscribe *subscription;

  while ((subscription = mqtt.readSubscription(1000))) {

    if (subscription == &bulbControl) {

      String command =

        (char *)bulbControl.lastread;

      Serial.print("Received: ");

      Serial.println(command);

      if (command == "ON") {

        digitalWrite(LED_PIN, HIGH);

        Serial.println("LED ON");

      }

      if (command == "OFF") {

        digitalWrite(LED_PIN, LOW);

        Serial.println("LED OFF");

      }

    }

  }

}

13. Challenges & Fixes

Challenge 1 — MQTT Connection Failure

Problem: The ESP32 could not establish a connection with Adafruit IO.

Solution: The Wi-Fi credentials, Adafruit IO username, AIO Key, MQTT server address, and network connection were checked.

Challenge 2 — Incorrect Feed Configuration

Problem: The ESP32 was connected to Adafruit IO but did not receive the LED command.

Solution: The MQTT feed name and subscription path were checked.

The feed was configured as:

username/feeds/bulb-control



Challenge 3 — Authentication Error

Problem: Adafruit IO rejected the MQTT connection.

Solution: The correct Adafruit IO username and AIO Key were entered into the ESP32 program.

Challenge 4 — LED Did Not Respond

Problem: The MQTT message was received but the LED did not change state.

Solution: The GPIO pin configuration and received message values were checked. The ESP32 Serial Monitor was used to verify whether ON or OFF was being received.

Challenge 5 — Internet Connectivity

Problem: MQTT communication requires Internet connectivity, unlike the local ESP32 web server used in Task 1.

Solution: The ESP32 was connected to a Wi-Fi network with Internet access before establishing the MQTT connection.

Final Result

The completed system demonstrates cloud-based LED control using ESP32, MQTT, and Adafruit IO.

The ESP32 connects to the Internet through Wi-Fi and subscribes to the bulb-control feed. When the user changes the control on the Adafruit IO dashboard, the command is published through MQTT. The Adafruit IO broker forwards the message to the ESP32, which processes the command and changes the LED state.

Final System:

Adafruit IO Dashboard → MQTT Broker → ESP32 → GPIO → LED

This task demonstrates the basic architecture of a cloud-connected IoT system and provides a foundation for controlling sensors and actuators remotely.
